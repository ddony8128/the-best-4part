# 한화 AI 솔루션 챌린지 — 인사 매칭 AI (자유주제)

> 팀이 던지는 아이디어를 계속 누적하는 기록 문서. 최신 결정이 위, 변경 이력은 하단 로그.

## 1. 확정 사항
- **주제**: Great Challenger 자유주제
- **아이템**: 인사 매칭 AI — TF·공석 발생 시 그룹 전체(계열사 불문)에서 적합 인재를 탐색·추천
- **제출물**: 3분 내외 영상(실제 작동 장면 필수) + 결과물(웹 URL 가능) + 서술 항목
- **평가표(100)**: AI 도구 활용 50(툴 선택 25 / 산출물 퀄리티 25), 문제 해결력 30(원인 분석 15 / 데이터 근거 해결책 15), 현업 적용 20(기대효과 10 / 구현 가능성 10)

## 2. 문제 정의
- **대상**: 사내공모·인력 배치를 맡는 인사부서, TF·공석 충원을 요청하는 현업. 매칭 대상은 그룹사 전체 임직원.
- **현재 모습(As-Is)**: 계열사·사업부를 넘나드는 인재 영입(cross-company)은 이미 많다. 문제는 이동이 아니라 **탐색·검토 방식**.
- **불편 3가지**
  1. 후보자군이 공고 인지·지원 여부·담당자가 아는 인력에 좌우됨 (접근성·인지도 편향)
  2. 경력·역량·프로젝트 경험이 계열사별로 분산되어 그룹 차원에서 종합 파악 어려움
  3. 직무 요구사항과 역량을 개별 대조하는 반복 업무, 공통 비교 기준·추천 근거 설명 부족
- **LLM이 필요한 이유**: 정량은 판단이 쉽지만 정성은 일일이 보기 어려움
- 부가 효과: 일이 안 맞아 힘든 사람의 문제도 어느 정도 해결
- 근거 수치: 연간 cross-company 건수는 공개 자료에서 못 찾음(임원 이동 사례만 확인). 수치는 **가정 명시 추정**으로 처리.

## 3. 전체 기능 4가지 (2026-10-21 확정)
| # | 기능 | 사용자 | 내용 |
|---|---|---|---|
| 1 | **인재 스캐닝·추천** | 인사 담당자 | JD + 관련 정보를 올리면 설정한 범위(기본: 한화 전체 계열사)의 직원을 전수 스캔 → 상위 N명 추천. 가중치를 조정하면 등수가 바뀜. |
| 2 | **추천서 작성** | 인사 담당자 | N명 중 1명을 고르면 "왜 이 직무에 적합한지 / 어떤 부분이 우려되는지"를 담은 추천서 생성. 상부 보고용·외부인이 봐도 추천 이유를 바로 이해할 수 있게. |
| 3 | **제안서 작성** | 인사 담당자 | 후보 당사자에게 보낼 메일 내용 생성: 이런 자리가 있고, 이런 성향·자격이 필요한데, 당신이 적절하므로 추천한다. |
| 4 | **임직원 셀프 진단·지원** | 임직원 | 인사가 올려둔 직무 중 지원하고 싶은 것을 고르면 내 평가(적합도)를 보여주고, 더 적합해지려면 무엇을 보충해야 하는지 정리. 그 화면에서 바로 지원 가능. |

1~3은 인사 담당자 기능, 4는 임직원 기능. 기존 참고 콘솔(§8)의 "인재 참여 제안"=기능 3, "상사 추천 보고"=기능 2의 사람 쪽 화면과 대응.

### 상세 흐름 (기능 1~3, 인사 담당자 관점)
1. 인사 담당자가 TF·공석의 업무 JD를 올린다.
2. **JD 구조화**: AI가 요구사항을 분해. 근거는 JD 원문 + 직무 적합 논문 + 유사 직무 고성과자 + 전임자 특성. 요구사항별 정량/정성 유형, 필수/우대, 가중치, 출처를 제안. **인사팀이 확인하는 Gate**.
3. **그룹 전수 탐색**: 정량 + 정성(LLM) 평가 → 종합 점수. 상위 N명 표시, 선택 후보는 정성 평가 보고서(잘 맞는 점 / 우려되는 점). 공모 지원자와 "숨은 후보" 구분 표시.
4. 후보 선택·제외, 가중치 조정 시 순위 재계산.
5. 후보 추천 리포트 + 관심 확인 메시지 초안(본인 동의 전제).

처리 구조: 입력(JD) → AI 처리(구조화·평가) → 자동화(탐색·점수) → 사람 확인(Gate·선택) → 출력(리포트·메시지)

## 10. 설계 원칙 (팀 기획안 12장에서 서비스에 반영할 것만 추림, 2026-10-21)
반영 제외: 10장 시범 운영 12주 일정, 12장 추진 체계·의사결정 요청, 09장 시스템 연계 상세, 11장 측정 방법론 대부분 → 실제 사업 보고용이라 데모·제출물과 무관. 효과 서술에만 일부 차용.

**화면·로직에 반영**
1. **AI는 지원, 결정은 사람**: 최종 배치는 현업 검증 + 본인 참여 의사 + 소속 조직 여건. (시작 페이지 운영 원칙 문구)
2. **적합성 ≠ 이동 가능성**: "적합한 경험이 있다"와 "실제 이동할 수 있다"를 분리. 참여 가능 조건·조직 협의는 별도 확인 항목.
3. **순위보다 근거**: 점수는 직무별 비교용 참고 지표. 성공 확률·전사 역량 순위로 해석 금지. 화면에 추천 이유 / 근거 문서 / 정보 확인일 / 미확인 요건 / 추가 질문을 함께 표시.
4. **요건별 비교 3상태**: 확인(근거 있음) / 확인 필요(근거 부족·전환 가능성 검토) / 정보 미확인(기록 없음 → 부족으로 단정하지 않음). **필수 요건 미확인이어도 자동 부적합 처리 안 함.**
5. **과대 해석 방지**: 교육 이수 ≠ 실무 숙련, 프로젝트 참여 ≠ 그 프로젝트 기술 전부 보유. 본인 역할 + 확인 가능한 근거로 판단.
6. **직원 정정**: 잘못 추출된 경력·역량을 본인이 정정 요청 → 인사 운영 기록.
7. **평가 제외 속성**: 성별·나이 등 직무와 무관한 속성은 점수 입력에서 제외.
8. **AI 매칭 5단계**: 공고 해석(LLM) → 프로필 정리(LLM) → 후보 검색(의미 기반, 표현이 달라도 연결: "경영지표 시각화" ↔ "Power BI 월간 실적 대시보드") → 요건별 비교(필수 자격 등 명확한 조건은 규칙) → 결과 설명(추천 이유 + 추가 확인 질문, 근거 없는 추론 제외).
9. **용어 통일**: 'BI 대시보드'와 '경영지표 시각화'를 같은 역량으로 연결.

**결과 예시 (기획안 8장, HR 매칭 화면에 사용)** — 가상 공고 "영업 데이터 분석 TF" (필수 SQL·매출 분석, 우대 대시보드, 3개월 주 2일)
| 항목 | 후보 A | 후보 B |
|---|---|---|
| SQL | 프로젝트 수행 기록에서 확인 | 교육 이수만 확인, 실무 확인 필요 |
| 매출 분석 | 매출 분석 프로젝트 확인 | 비용 분석 경험, 전환 가능성 검토 |
| 대시보드 | Power BI 구축 확인 | 정보 미확인 |
| 참여 가능 | 본인·조직 확인 필요 | 본인·조직 확인 필요 |
| 추가 질문 | 분석에서 본인이 맡은 범위는? | SQL을 실무에 적용한 사례는? |

**효과 측정 지표 (서술에 차용)**: 공고당 탐색·검토 시간 / 상위 K명 중 검토 적합 비율 / 기존 방식에서 못 찾은 적합 후보 수 / 근거 오류·과장 비율. 시간 절감은 "업무 여력 확보"로 해석하고 인건비 절감으로 바로 환산하지 않음.

### C. 가장 큰 현실 제약
1. **계열사는 별도 법인** → 다른 계열사 직원의 인사 정보를 쓰는 것은 제3자 제공에 해당해 **본인 동의가 필요**할 가능성이 큼(개인정보보호법). 해결안: **"그룹 인재풀 등록" 동의(opt-in)** — 동의한 임직원만 스캔 대상. 숨은 후보 = "공모엔 지원 안 했지만 인재풀에는 등록한 사람".
2. 성과평가를 배치 목적으로 쓰는 범위는 사내 규정 확인 필요.
3. 정성 항목 대부분은 정형 데이터가 아니라 문서 텍스트 → LLM이 필요한 이유이자, 근거 원문을 반드시 함께 보여 줘야 하는 이유.
4. 데이터 신뢰 등급을 화면에 표시 제안: **시스템 확정 / 문서 근거 / 본인 기재 / 면담 확인 필요**.

**결정(2026-10-22)**: 실제 데이터는 쓰지 않고 가상 데이터만 쓴다. 단, 실제 인사 시스템의 내보내기 구조를 그대로 따라 도입 시 데이터만 바꾸면 되게 한다 → `docs/data-dictionary.md`, `data/generate.mjs`.
