# TALENT LINK 제출 양식 작성안

> 각 칸에 그대로 붙여 넣을 수 있게 일반 텍스트로 썼습니다. 숫자는 모두 실제 서비스·DB·영상에서 확인한 값입니다.

---

## 과제명
계열사를 초월하여 인재를 연결하는 TALENT LINK

## 현재 상태
완성
(실제 DB·AI가 연결된 웹 서비스로 배포되어 있으며, 인사 담당자·임직원 화면 모두 실제로 작동합니다. 임직원·지원서 데이터는 실제 정보가 아닌 직접 만든 데이터입니다.)

## 프로젝트 주제
Great Challenger · 자유주제

## 팀원
김대헌, 김도현, 안찬호, 이지은, 임광현

## 해결할 문제와 대상

■ 프로젝트 목적
그룹 내 인력 수요(조직)와 인적 자원(임직원) 사이의 매칭 비효율을 해소하고, 데이터 근거로 적합 인재를 먼저 찾아 추천하는 체계를 만드는 것이 목적입니다.

■ 추진 배경 및 필요성
- 후보자 탐색의 한계: TF 구성이나 공석 충원 시 자발적 지원자 또는 이미 알려진 추천 인력에만 의존해, 그룹 안의 숨은 적합 인재가 검토 대상에서 빠집니다.
- 통합 비교 체계의 필요성: 계열사·조직의 벽을 넘어 인재를 찾고, 직무 요구사항과 임직원의 경험·역량을 같은 기준으로 비교할 수 있는 그룹 통합 인재 매칭 체계가 필요합니다.

■ 서비스 대상
- 주요 이용자: 사내공모·인력 배치를 담당하는 인사 담당자, TF·공석 충원을 요청하는 현업 조직
- 매칭 대상: 정보 제공에 동의하고 인재풀에 등록한 그룹 임직원 (시연: 한화에어로스페이스·한화오션·한화시스템 3개 계열사, 247명)

■ 기대 가치
- 조직: 외부 채용 전에 그룹 내 적합 인재를 먼저 발굴해 적재적소에 배치
- 임직원: 지원하지 않았더라도 내 경험에 맞는 자리를 제안받고, 같은 기준으로 적합도를 확인한 뒤 도전

## 현재 상황과 불편

핵심 원인: 그룹 전체 임직원을 공고마다 사람이 직접 검토하는 것은 시간상 불가능합니다. 그래서 검토 범위를 '지원자 · 아는 사람 · 우리 계열사 · 같은 직무명'으로 좁힐 수밖에 없고, 그 밖에 있는 적합 인재는 처음부터 보이지 않습니다.

1. 시간의 벽 — "다 볼 수 없으니, 지원자만 본다"
- 현황: 사내공모와 인력 배치는 자발적 지원이나 담당자·현업의 개인적 추천에 의존합니다.
- 원인: 한 사람의 경력·성과·자격을 공고의 요건 하나하나와 대조하려면 시간이 걸립니다. 1명에 10분만 잡아도 247명이면 약 41시간, 그룹 전체라면 공고마다 수천 시간이 필요해 현실적으로 불가능합니다.
- 문제: 공고를 못 봤거나, 지원을 망설였거나, 인지도가 낮은 적합 인재는 검토 대상에서 빠집니다.
- 시연 데이터: 「마케팅 및 글로벌 브랜드 전략(한화에어로스페이스)」 공고의 지원자는 4명이었지만, 247명을 모두 검토하자 추천 상위 10명 중 9명이 공모에 지원하지 않은 임직원이었습니다.

2. 계열사의 벽 — "다른 계열사 인재는 사실상 검토 대상이 아니다"
- 현황: 경력·역량·프로젝트 경험·자격·평가 기록이 계열사·조직별로 흩어져 있습니다.
- 원인: 다른 계열사의 인재 정보를 같은 틀로 모아 비교하는 체계가 없고, 사람이 일일이 찾아볼 여력도 없습니다.
- 문제: 그룹 안에 맞는 사람이 있어도 외부 채용이나 같은 계열사 안의 후보로만 해결하게 됩니다.
- 시연 데이터: 위 공고(한화에어로스페이스)의 추천 상위 10명 중 7명이 다른 계열사(한화오션 4명, 한화시스템 3명) 소속이었습니다.

3. 직무명의 벽 — "직함이 다르면 검색에 걸리지 않는다"
- 현황: 후보를 찾을 때 부서명·직함·직무명 같은 키워드에 의존합니다.
- 원인: 실제로 맞는 것은 '무슨 일을 해 봤는가(경험)'인데, 찾는 기준은 '무슨 직함인가'입니다.
- 문제: 다른 이름의 직무에서 같은 경험을 쌓은 사람, 즉 생각지 못한 직무 간 연결을 놓칩니다.
- 시연 데이터: 마케팅 공고의 1위 후보는 마케팅 직함이 없는 한화시스템 해외사업팀 임광현 과장이었습니다. 해외 전시회 캠페인, 영문 세일즈키트 제작 경험이 공고 업무와 맞닿아 있었습니다.

4. 기준과 근거의 부재 — "왜 이 사람인지 설명하기 어렵다"
- 현황: 요건과 후보 역량을 매번 수작업으로 대조하고, 추천 사유도 직접 씁니다.
- 원인: 공고 요건이 '확인할 수 있는 항목'으로 쪼개져 있지 않고, 판단 근거가 문서로 남지 않습니다.
- 문제: 후보 간 비교 기준이 사람마다 다르고, 상사 보고나 당사자 제안 때 근거를 제시하기 어렵습니다.

→ TALENT LINK는 AI가 그룹 전체를 같은 기준으로 대신 읽어, 사람이 볼 수 없던 범위(계열사 · 직무명 · 지원 여부를 넘어)까지 후보를 넓히고, 사람은 근거를 보고 결정만 하도록 바꿉니다.

## 활용 자료·데이터

- 직무 공고(JD) 45개: 한화에어로스페이스·한화오션·한화시스템의 공개 채용공고를 바탕으로 직무·담당 업무·필수/우대 요건을 정리. 공고마다 자격증·직무 경력 같은 정량 필수 조건 1~2개를 설정
- 공고별 참고 자료 45건: 전임자 인수인계 내용, 고성과자 행동 패턴, 직무 연구 근거 (직접 작성)
- 직무 연구: 빅파이브 성격 요인과 직무 성과의 관계를 다룬 메타분석 논문(Barrick & Mount 1991, Hurtz & Donovan 2000, Judge 외 2002, Vinchur 외 1998 등)을 Gemini 딥리서치로 정리 → 11개 직무군별로 중요한 성향을 '관찰 가능한 행동 근거'로 바꿔 공고 분석에 반영 (성격 점수는 매기지 않음)
- 임직원 프로필 더미 데이터 247명 (한화오션 91 · 한화시스템 96 · 한화에어로스페이스 60): 직무 경력, 역량 수준, 성과·평가 기록, 자격, 수행확인서 등 근거 문서
- 사내공모 지원서 더미 데이터 158건
- 프로필 사진 247장: AI로 만든 합성 인물 사진
- 실제 임직원 정보·회사 기밀은 사용하지 않았습니다. 성별·나이 등 직무와 무관한 정보는 분석에 쓰지 않습니다.

## 사용한 AI·자동화 도구

- Claude (Anthropic API, Sonnet 모델): 서비스 안의 AI 기능 전체
  · 공고 분석: JD와 참고 자료를 읽고 요건 8개와 평가축 중요도를 제안
  · 후보 판정: 요건마다 '확인 / 확인 필요 / 정보 미확인'과 근거 문장·출처를 작성
  · 추천서·제안서(Job Offer Letter) 초안 작성, 임직원 셀프 진단
  · 선택 이유: 긴 인사 문서를 읽고 정해진 형식(JSON)으로 근거를 남기는 데 강하고, 대량 판정은 Batch API로 비용을 50% 줄일 수 있음
- Claude Code: 웹 서비스 구현, 자동 테스트, 데이터 생성, 시연 영상 제작 자동화
- Gemini: 딥리서치(직무 연구 논문 정리), TTS(영상 내레이션 음성)
- ChatGPT: 기획 아이디어 정리, 문서 작성 보조, 화면 단위 UI 개선안 제작
- 자동화·인프라: Supabase(DB), Vercel(웹 배포·서버 기능), Playwright(화면 자동 테스트·녹화), Remotion(코드로 영상 편집)

## AI·자동화 흐름

입력 → AI 처리 → 사람 확인 → 자동화 → AI 처리 → 사람 확인 → 출력

1. 입력: 공고(JD) + 참고 자료(인수인계·고성과자 패턴·직무 연구) + 그룹 인재풀 프로필
2. AI 처리 ①: Claude가 공고를 요건 8개(필수/우대)와 평가축 5개의 중요도로 정리
3. 사람 확인 ①: 인사 담당자가 요건과 중요도를 확인·수정해야 스캔이 시작됨 (Gate)
4. 자동화: 자격·직무 경력 같은 정량 필수 조건(Yes/No)으로 먼저 거름 → 시연 공고 기준 247명 중 34명 (45개 공고 평균 AI 판정 대상 88% 감소)
5. AI 처리 ②: 통과자 전원을 요건별로 판정하고 근거·출처를 남김 → 점수 = 요건 판정 65% + 인사 기록 지표 35%, 중요도를 바꾸면 순위가 즉시 다시 계산됨
6. 사람 확인 ②: 상위 후보의 요건별 근거, 우려되는 점, 면담 질문을 보고 담당자가 판단
7. AI 처리 ③: 추천서(상사 보고용)와 제안서·오퍼 레터(당사자용) 초안 작성
8. 사람 확인 ③: 담당자가 화면에서 바로 수정·저장
9. 출력: 상사 보고, 당사자에게 제안 발송 → 임직원이 같은 기준으로 셀프 진단(AI) → 바로 지원 → 인사 콘솔에 도착, 모든 과정이 운영 기록에 남음

운영 원칙: AI는 찾고, 결정은 사람이 한다 / 정보 미확인 ≠ 역량 부족(자동 탈락 없음) / 성별·나이 등 직무와 무관한 정보 배제

## 만든 과정

[역할 분담]
- 설계: 임광현
- 자료조사: 이지은, 김대헌
- 구현: 김도현
- 자료 제작: 안찬호

[주요 제작 단계]
1. 문제 정의와 데이터 설계: 공고 45개, 임직원 247명, 지원서 158건, 공고별 참고 자료와 직무 연구 자료를 같은 형식으로 정리
2. AI 매칭 파이프라인 구현: 공고 분석 → 정량 조건 필터 → 요건별 근거 판정 → 점수 계산 → 추천서·제안서 작성까지 실제 Claude API와 DB로 연결
3. 인사 담당자 화면(AI 인재 매칭·인사 콘솔)과 임직원 화면(받은 제안·셀프 진단·지원)을 하나의 흐름으로 연결
4. 웹 배포, 로그인·권한 분리, 자동 테스트, 시연 영상 제작

[시행착오와 개선]
1. 근거 없는 '상위 30명' 컷 → 정량 필수 조건 필터: 처음에는 키워드 점수로 상위 30명을 잘랐는데 기준이 임의적이었습니다. 자격증·직무 경력처럼 기록으로 확인되는 Yes/No 조건으로 먼저 거르고, 통과자는 전원 AI가 판정하도록 바꿨습니다.
2. 가중치 합계 오류 → 4단계 중요도: % 숫자를 직접 넣으면 합계가 100%를 넘는 오류가 있어, '매우 중요·중요·보통·덜 중요' 4단계를 고르면 비율이 자동 계산되도록 바꿨습니다.
3. 점수만 보이던 결과 → 근거 중심: 요건마다 확인 여부와 근거 문장·출처를 보여 주고, 기록이 없는 요건은 '정보 미확인'으로 따로 표시해 자동 탈락이 생기지 않게 했습니다.
4. AI 대기 시간 → 미리 판정: 247명을 실시간으로 판정하면 오래 걸려, 공고별 판정 1,346건을 미리 해 두고 같은 분석이면 그대로 재사용, 없으면 그 자리에서 분석하도록 했습니다. 대량 판정은 Batch API로 비용을 줄였습니다.
5. 권한과 보안: 사내 계정(클레버스) 아이디로 로그인하되 인사 담당자와 임직원의 권한·화면을 분리하고, 임직원 본인 화면에서는 정량 기록은 보여 주되 인사팀의 정성 평가는 가렸습니다. DB 접근 키는 서버에만 두었습니다.
6. 화면 개선: 글자가 작고 흐리다는 피드백으로 토스 스타일을 참고한 디자인 시스템을 만들어 적용하고, 화면별 정보량을 줄였습니다. 후보 목록에는 프로필 사진을 넣었습니다.
7. 문서 기능: 추천서·제안서 작성 중 진행 화면, 화면에서 바로 수정·저장, PDF 다운로드, 제안서에 Job Offer Letter 자동 첨부, 발신자·수신자 자동 지정을 넣었습니다.

[검증 방법]
- 자동 브라우저 테스트로 전체 흐름(로그인 → 분석 → 스캔 → 추천 → 문서 → 임직원 진단·지원 → 인사 콘솔)을 매번 확인 (기본 33개 항목, 피드백 반영 27개 항목, 실제 DB·AI 연결 상태 전 구간 테스트)
- AI 판정 결과는 정해진 형식(JSON)과 검증 스크립트로 누락·오류를 점검

- 인사 콘솔: 공고 관리, 지원자 검토, 인재 참여 제안, 상사 추천 보고, 운영 기록
- 임직원 화면: 받은 제안 확인 → 같은 기준의 셀프 진단(요약 → 요건별 근거 → 지원) → 바로 지원
- 운영 원칙: "AI는 찾고, 결정은 사람이 한다." 점수보다 근거(확인·확인 필요·정보 미확인, 우려되는 점, 면담 질문)를 보여 주고, 정보가 없다는 이유로 자동 탈락시키지 않으며, 성별·나이 등 직무와 무관한 정보는 배제합니다.

2. 무엇이 달라지는가 (시연 공고 기준)
- 후보 탐색 범위: 지원자 4명 → 그룹 인재풀 247명
- 숨은 인재 발견: 추천 상위 10명 중 9명이 공모에 지원하지 않은 임직원
- 계열사를 넘은 연결: 추천 상위 10명 중 7명이 공고를 낸 회사가 아닌 다른 계열사 소속
- 직무명을 넘은 연결: 1위 후보는 마케팅 직함이 없는 해외사업팀 소속 (경험 기준으로 발견)
- AI 판정 대상: 정량 조건으로 먼저 걸러 247명 → 34명 (86% 감소). 45개 공고 전체로는 공고별 6~63명, 평균 88% 감소 — 전원 판정했다면 11,115건이었을 AI 판정을 1,346건만 수행
- 근거 문서화: 추천 후보의 모든 요건에 근거·출처가 남음
- 문서 작성: 추천서·제안서 초안을 AI가 약 10초 안에 작성하고, 담당자는 검토·수정만 함
- 임직원 경험: 지원한 적 없는 계열사에서 먼저 제안을 받고, 셀프 진단으로 적합도를 확인한 뒤 지원

## 효과와 활용 가치

1. 시간
- 공고 하나에 대해 그룹 전체 후보를 찾고, 요건별로 대조하고, 추천서·제안서를 쓰는 과정을 한 화면에서 처리합니다.
- 사람이 직접 하던 서류 대조와 문서 초안 작성은 AI가 맡고, 담당자는 확인과 판단에 시간을 씁니다.

2. 품질
- 모든 후보를 같은 요건·같은 기준으로 비교하고, 판단 근거가 문서로 남아 상사 보고와 사후 검토가 쉬워집니다.
- 직무 연구(메타분석 논문)를 반영해 공고마다 중요한 역량을 정리하므로, 담당자 개인의 경험에만 의존하지 않습니다.
- 정보가 없는 요건은 '정보 미확인'으로 구분해 면담에서 확인하도록 안내합니다.

3. 경험
- 임직원은 추가 설문 없이 기존 인사 기록으로 인재풀에 참여하고, 받은 제안의 이유와 내 적합도를 같은 기준으로 확인할 수 있습니다.
- 인사 담당자는 5단계 화면을 따라가기만 하면 분석부터 문서 발송까지 끝납니다.

4. 현실적 구현 가능성과 확산
- 웹 서비스·DB·AI가 실제로 연결되어 작동하며, 실제 인사 시스템(HRIS) 데이터를 같은 형식으로 넣으면 그대로 쓸 수 있는 구조입니다.
- 정량 조건 사전 필터와 Batch API로 AI 비용을 낮췄고, 판정 결과를 저장해 재사용합니다.
- 사내공모 외에도 TF 구성, 프로젝트 인력 충원, 계열사 간 순환 배치에 같은 흐름을 적용할 수 있습니다.
